# 智能体工作平台设计

本设计把用户的目标拆成可验收的机制。模型的能力、供应商可用性和审美判断不能由插件保证；插件必须保证失败可见、来源可查、修改不会悄悄覆盖人的工作、未检验的产物不会被标为通过。

## 1. 用户、项目、会话、任务和资产

用户身份默认为本机个人配置。项目 UUID 随 `.blend` 保存；同一项目可以拥有多个独立会话和多个生产任务。另存文件仍属于同一项目，需要独立记忆时使用 Fork Project。会话是讨论记录，生产任务是执行记录，资产是带稳定 ID 和内容指纹的输出，三者互相引用而不混成一段聊天文本。

主架构智能体负责需求、装配关系、单位/坐标系、部件边界、依赖和验收指标。专家任务只接收目标相关记忆、输入资产、依赖结果、明确的写入范围和质量合同。独立模型请求可以并行，Blender 主线程场景提交必须串行。每次提交检查输入指纹；人工编辑导致指纹变化时保留分支候选并报冲突，绝不静默覆盖。

## 2. 记忆不是提示词日志

| 层 | 保存什么 | 更新原则 | 使用范围 |
|---|---|---|---|
| 工作上下文 | 当前请求、近期原文、选择区域、场景事实、任务状态 | 每次请求重新构建，预算有上限 | 单次调用 |
| 短期记忆 | 会话内待办、暂定选择、未决问题 | 默认一天过期，原文仍可查 | 当前会话 |
| 项目记忆 | 单位、风格、部件接口、约束、确认的决策 | 来源、版本、矛盾并存，确认后替代 | 同一项目 |
| 长期个人记忆 | 用户主动确认的习惯、偏好、工作方式 | 不从一次模型猜测升级为事实 | 同一本机用户的项目 |
| 程序性经验 | 经验证的工作方法、失败原因与适用条件 | 必须保留执行证据，不能把单次失败泛化 | 明确适用的项目或用户 |
| 情景档案 | 完整对话、压缩检查点、运行报告、质量证据 | 原文持久保存；压缩不删除原文 | 可审计，不全部塞给模型 |

记忆字段包含 ID、scope、project/thread/user、kind、key、value、status、revision、来源 turn ID 和原文引用、创建/更新时间、过期时间。数据库使用事务、WAL、外键和乐观版本锁。旧版本保留，用户修改必须匹配自己看到的 revision，避免两个窗口互相覆盖。

生命周期：提取候选 → 检查来源 → 去重/冲突 → 用户确认或保留候选 → 检索 → 过期/替代/遗忘。模型只能提出候选，不能赋予自己事实权限。自动提取的引用必须确实出现在同一项目的用户原文中；模型自述和远端资产内的指令不构成用户偏好证据。相同 key 的不同 value 进入冲突，不能以“最新一次模型输出”覆盖已确认记忆。确认新版本显式替代冲突的旧版本。拒绝、编辑、恢复和遗忘均有对应操作；遗忘删除正文和历史版本，不能只隐藏检索结果。

检索先限定权限和范围，再按词语/中文双字、重要度、时间排序，强制预算截断。候选和矛盾记录不作为事实注入；未确认数量在界面可见。本地词汇检索明确标为词汇检索，不假称向量语义搜索。长期记忆是数据，永远不高于本轮用户要求。密钥模式被过滤；本地数据库不是加密保险箱，普通对话仍可能包含个人信息，用户应控制保存目录和备份。

## 3. 自动压缩与真实多轮对话

对话永久保存逐条原文和调用结果。达到上下文阈值时，后台摘要模型生成目标、约束、决策、进展、未决问题和资产引用，并标注来源 turn ID。保存摘要检查点和覆盖范围，近期原文继续逐条传给模型。模型摘要失败时使用可追溯的抽取式摘要并显示降级，不能删除历史或假称语义压缩成功。摘要仍属模型推导，重要约束优先来自已确认项目记忆与本轮原文。

每轮由：固定权限/行为说明 + 已确认相关记忆 + 带来源摘要 + 场景事实 + 最近原文 + 当前输入附件构成。预留输出预算；不能把当前用户请求静默截断。压缩和提取占用真实模型调用，界面明确开关及预算，不隐藏成本。

## 4. 多模态与人在回路中

附件保存媒体类型、散列、路径与角色（参考图、草图、精修遮罩、源模型、音轨、视频等）。视觉聊天传递真实图像数据。通用生成桥接明确上传附件字节并把资产句柄传入任务，不把本地路径假装成远程可读取输入。原生供应商只暴露实际支持的模态；例如未实现视频理解的配置不能假称理解视频。

Blender 原生绘制/Grease Pencil 和视口截图提供草图入口，用户在编辑模式选择顶点/面后可捕获区域锚点。精修合同同时保存对象 ID、拓扑/内容指纹、选择索引及坐标；拓扑变化使旧区域选择失效。任意自由文本无法数学保证“精确”，必须有写入范围检查、分支预览、人工接受和版本冲突处理。

## 5. 执行隔离与协作协议

模型 HTTP 请求在标准 Python 子进程执行。生成代码在独立 Blender 后台进程处理输入副本，带 AST 限制、进程期限、输出目录和输入/输出清单；该进程隔离保护当前编辑会话，不是操作系统安全沙箱。生成代码不接收 API 密钥。成功输出必须通过合同与原生检查才允许合并。任务不能通过修改自己的 JSON 状态绕过检查。

任务合同描述 asset scope、输出类型、尺寸/面数边界、必需对象和材质、装配单位/坐标、依赖和证据。并行任务必须拥有不同写入资源；重叠资源排队。独立失败不抹除成功任务，下游阻塞；重试保留已完成产物。取消杀死本地子进程，远端已付费任务需另查供应商状态。崩溃恢复只恢复可证实的检查点，不自动重发可能已计费的 POST。

## 6. 强制自检与高质量交付

任何模型产物都至少进行对应类型的文件/结构检查。3D 包含非空、有限数值、退化面、模型合同、材料和适用拓扑检查。闭合/流形要求由用途决定，开放布片不能因不是闭合体一律失败。艺术/语义质量由带真实渲染证据的视觉评审或人工评审补充；只有文本事实时必须注明未做视觉检验。质量报告绑定资产指纹，人工修改会使旧 PASS 失效。修复次数有上限，失败不能改名为“完成”。

导出流程先检查当前版本的原生质量门，再检查所要求的评审证据。高质量是可配置的验收合同和可见证据，不是模型口头的 passed:true。渲染预览、质检报告、输入来源与导出物一起进入运行目录。

## 7. 主动服务与运行治理

主动检查默认只给建议：过期质检、冲突记忆、缺少材料/UV、未配置能力、任务停滞、预算不足。编辑场景和收费生成仍由用户发起的生产任务控制。界面提供最大并发、调用/修复预算、取消、任务选择、记忆审阅和附件管理。没有独立显式许可时，不因“主动智能”自行上传项目或购买服务。

## 8. 验证与边界

使用纯 Python 回归测试检查事务、项目隔离、冲突、版本锁、压缩来源、预算和协议。使用本机 Blender 检查真实注册、隔离执行、人工修改冲突、模型/图片/视频/音频导入、质量失败阻断导出、取消与重试。供应商协议使用本地服务器验证；没有真实凭据不能声称付费模型已实测。不同 Blender 版本按能力探测和 CI 矩阵逐步验证，报告区分设计支持与已经实测。
