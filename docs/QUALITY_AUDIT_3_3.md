# 3.3 深度检查与生产验收

目标是让任务的输入、协作、编辑、检查、恢复和交付形成可验证的流程。
“模型说完成”“脚本没报错”“文件存在”都不足以作为完成证据。
当前稳定版以 2026-09-22 核实的官方 Blender 5.2.2 LTS 为基线。

## 检查矩阵

| 环节 | 发现的缺口 | 3.3 行为及回归 |
|---|---|---|
| Blender 版本 | 旧矩阵停在 5.1；5.2 GN 输入改为 RNA | `set_geometry_input` 双接口；真实修改参数后指纹必须改变；对象输入必须纳入依赖范围 |
| 细粒度修改 | 嵌套色带、相机设置、重复绘制像素可能漏检 | 嵌套 RNA、色带／曲线映射／景深、真实像素指纹；区域外通用属性变化被拒绝 |
| 场景提交 | 修改世界、帧率或渲染设置可能只存在于工作进程 | 显式场景权限、序列化传递、临时场景复检、成功后提交；无权限修改明确失败 |
| 对象替换 | 先链接再重映射使 3.6 重复计算集合引用 | 先转移既有引用，再补充目标集合；断言原集合归属完整且用户计数无泄漏 |
| 审阅与恢复 | 对象没变，但时间线／单位／渲染条件已变 | 交付版本同时覆盖对象与场景；旧批准／旧检查点不能继续使用 |
| 材质／UV | 有材质槽或 UV 层并不代表可用 | 检查面分配、材质输出、连接图像、外部纹理和塌缩 UV |
| 动画 | 存在 action 或空曲线可能被当作成功 | 检查绑定的 action slot、非空有效通道、不同关键时刻、形态键及材质节点动画；检查要求的时间跨度 |
| 运动质量 | 单帧正常但中间帧越界或变形 | 在有限的均匀点、关键时刻或指定帧检查求值后网格；返回帧号和诊断，恢复用户当前帧／子帧 |
| 视觉证据 | Workbench 不能表达真实着色节点 | 保留三视图；材料合同增加 Cycles CPU 工作室实渲，动画合同增加标记帧预览；发送数量受预算约束 |
| 文件交付 | 导出返回成功，但可能没有有效／可达网格 | 检查 GLB 头、长度、JSON、嵌入图像／buffer、访问器边界和可达网格，通过后原子替换 |
| 原生数据 | GLB 无法表达全部程序化材质和世界 | 一并交付原生 `asset.blend`，保留工作流范围内的场景设置和原生数据 |
| 历史记忆 | 成功会覆盖之前失败的原因 | v3 保存追加式执行事件，重复事件幂等，旧尝试不得覆盖新尝试 |
| 摘要竞争 | 用户遗忘后，在途摘要可能重新写入旧内容 | 摘要携带记忆 epoch；用户审阅／遗忘后拒绝旧摘要并重新构建上下文 |
| 长会话 | 用近期窗口作为压缩源会跳过更早原文 | 从最早未覆盖的原文推进；10,012 条消息回归；覆盖编号留本地，只发送模型实际需要的引用 |
| 固定约束 | 对话保护固定约束，但专家提示可能丢弃 | 专家检索同样保留固定约束；预算不足明确停止，不静默删除要求 |
| 记忆导出 | 检索窗口会截断事件或版本 | 项目 JSON 包含全部执行事件和记忆版本；检索窗口与数据备份分离 |
| 转写输入 | 启动后修改音频选择可能改变实际请求 | 固定内容哈希，发送前验证并复制确切字节；过期输入拒绝提交 |
| 地形 | “细分”参数未实际生效 | n×n 四边形，(n+1)² 顶点，按请求尺寸与确定性高度生成 |
| 散布 | 物体落在包围盒顶面而非目标表面 | 求值后网格三角化，按世界空间面积抽样，法线对齐、保留源尺寸，局部随机数发生器 |
| 安装与平台 | 只验证源码，无法证明安装包工作 | 每个 Blender 版本验证源码、传统安装、适用扩展、扩展内进程和 manifest；验证包使用独立目录 |

## 可直接编辑的质量合同

以下片段是生产计划中的任务定义。它们需要真实的模型配置和实际前置任务。

```json
{
  "id": "animate",
  "expert": "animator",
  "prompt": "Animate the existing mechanism over frames 1–120; keep it inside the agreed assembly envelope.",
  "depends_on": ["materials"],
  "contract": {
    "require_geometry": true,
    "require_materials": true,
    "require_uv": true,
    "require_animation": true,
    "animation_range": [1, 120],
    "sample_frames": [1, 30, 60, 90, 120],
    "max_vertices": 200000,
    "max_extent": 4
  }
}
```

`animation_range` 要求可用关键时刻覆盖该区间；它不保证运动表达意图。
`sample_frames` 最多 12 个严格递增的整数帧。未指定时动画任务采样端点、
均匀内点和有限的关键时刻。此处的动画检查不是全时域碰撞／物理稳定性证明。
复杂绑定还应由角色／动画专业验收检查变形、接触、穿插和节奏。

```json
{
  "id": "presentation",
  "expert": "lighting",
  "prompt": "Create the final camera and lighting, configure world and output resolution, preserve all existing objects.",
  "depends_on": ["animate"],
  "contract": {"allow_scene_settings": true, "require_materials": true}
}
```

场景权限与 `part_id` 不可并用，也不可用于局部顶点精修。并行部件保持共享场景不变；
最终装配／灯光任务等待依赖结束后执行。允许提交的是代码中的显式白名单：世界、
范围内相机、时间范围、帧率、单位、引擎、透明背景、分辨率和基础色彩管理。
Compositor、VSE、第三方渲染器自定义设置和模拟缓存不在这份场景设置协议内。

## 可检查的输出

- `run.json`：任务、来源、预算、修复、合同、当前交付版本、文件哈希、质量报告。
- 分支 `candidate.blend`：保留待合并的候选，冲突时可手工检查。
- `preview.png`、`preview-back.png`、`preview-top.png`：几何三视图。
- `preview-material.png`：材料合同要求时生成的 Cycles CPU 16 samples / 384² 工作室预览。
- `preview-frame-<n>.png`：动画合同的端点预览；具体几何检查帧在 `sampled_frames` 中。
- `asset.glb`：已检查的交换文件，包含导出的相机和灯光。
- `asset.blend`：工作流范围内的原生场景；未预先打包的外部纹理／缓存继续使用文件引用。

Cycles 预览使用临时工作室灯光，结束后恢复设置。它证明材质节点可以实际渲染，
不能替代最终作品的灯光／构图评估。评审模型只可依据实际附带的图像判断；
上下文预算可能限制视图数量，报告会记录实际数量。人工批准默认保留。

并执行独立的安装与工作进程烟雾检查。命令和逐提交证据见 [VALIDATION.md](VALIDATION.md)。

长视频和世界模拟、复杂缓存及第三方插件仍需相应服务与具体项目验收。
